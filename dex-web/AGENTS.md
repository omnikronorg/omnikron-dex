### Non-negotiable rules

1. **Never edit the `nextjs-agent-rules` block** at the top of this file; write content below it.
2. **Never edit `contracts/src/periphery/libraries/PairInitCode.sol`** — it is AUTO-GENERATED. If you change `Pair.sol`, run `forge script script/GenerateInitCodeHash.s.sol:GenerateInitCodeHash` and redeploy the `Factory` **and** `Router` (the hash is embedded in `AmmLibrary`).
3. **No hard-coded addresses** in components or hooks: always use `getChainConfig(chainId)` / `getTokenList(chainId)`. If the network lacks a configuration, handle the `null` case and display a warning—do not invent values.
4. **Do not add new Web3 dependencies** (nor web3.js, unless explicitly requested, but you can make suggestions if it's applied). The stack is viem + wagmi + TanStack Query.
5. **ABIs are minimal and hand-written** in `lib/abi/*.ts` (`erc20`, `factory`, `pair`, `router`), using `as const`, a header comment, and 4-space indentation. Do not generate massive files from `contracts/out`; include only the functions/events that are actually used.
6. **Do not commit** `.env*`, `node_modules/`, or `.next/`. `contracts/broadcast/` and `contracts/deployments/` **are versioned** (deployment audit artifacts).
7. Stick to the scope: no sweeping refactors, new files, or abstraction layers without a genuine need.



### Data Layer (config, tokens, networks)

- Should be stored and read from the database (MongoDB).
- `Token { address, symbol, name, decimals, logoURI, isNative? }` + `getTokenList`, `findToken`, `getNativeToken`, `getFirstNonNativeToken`. The native token is represented with `isNative: true` and the network's `wrappedNative` address.
- `Network { id, name, symbol, logoURI, wrappedNative }` + `getNetworkList`, `findNetwork` (fallback "Unknown").


## Web3 Rules

- Reads via wagmi hooks (`useReadContract`/`useBalance`/`useBlockNumber`) with `query.enabled` guarding valid address/chainId; writes via `useWriteContract` + `useWaitForTransactionReceipt`.
- Swap quote: `getAmountsOut` via `routerAbi` (or direct query of the pair's reserves). Never fabricate the price on the client side.
- Any ERC-20 requires an `allowance` before `swapExactTokensForTokens` / `addLiquidity`: approve (with an optional infinite allowance check) and only then send the transaction.
- Native: use `swapExactNativeForTokens` / `swapExactTokensForNative` + `addLiquidityNative`/`removeLiquidityNative` with `value`, keeping the wrapped asset hidden both internally and visually.
- Every transaction requires a `deadline`, `amountOutMin`/`amountInMax` derived from the configured slippage, and a chain check (`useChainId` vs. the UI's `chainId`) before signing.
- Handle `user rejected`, `insufficient funds`, gas issues, and reverts with clear messages; disable buttons while `isPending` or `isConfirming`.
- Keys and RPCs only via `NEXT_PUBLIC_*` in `.env.local` or reading from wagmi or related — never hard-code RPCs in the component.

## Coding Guidelines

- **Framework:** Next.js (App Router by default).
- **Language:** TypeScript in strict mode.
- **Style:** React functional components, Tailwind CSS usage for styling except colors. Colors, Background Colors, Border Colors, Shaddow Colors and all other related color rules inside `app/globals.css`.
- **Limits:** Never modify global configuration files without explicit permission.
- **Indentation:** Preference for using four space characters per indentation level.
- **Curly braces:** Opening curly braces on a new line (Allman style)

## Coding Style for TypeScript, React, Next.js (TS/TSX)

- **4-space** indentation; code blocks separated by blank lines; comments explaining non-obvious blocks.
- `{` on a **new line** in function/component declarations; in inline callbacks, it stays on the same line (`onClick={() => { ... }}`).
- No `;` at the end of a function declaration; follow the style of the file you are editing.
- `if(cond)` without a space after `if`, with `{` on a new line.
- Components: PascalCase file (`components/SwapForm.tsx`), `function Name(props) { ... }` + `export default Name`, `NameProps` interface declared above, callbacks as props named `onX`/`OnX` + verb (`changeChainId`, `OnTokenSelected`).
- `"use client"` only where there is state/hooks (currently: `app/(swap)/swap/page.tsx`, `SwapForm.tsx`, `SwapSettings.tsx`).
- UI text in **English**; code comments in **English** (e.g., "Inteface rules").
- Next.js 16: use the generated global types (`PageProps<"/swap">`, `LayoutProps<"/">`) and the guides in `node_modules/next/dist/docs/` before writing new framework code.


## Visual and Theme

- Tailwind 4 (inline utilities) **+** semantic classes defined in `app/globals.css` (`.swap-*`, `.header-*`), always based on CSS variables (`--color-primary`, `--color-background2/3/4`, `--color-default1..7`, `--color-warning`, `--color-critical`).
- No hardcoded hex values ​​in components: if a style is missing, create a semantic class in `globals.css`. (Technical debt: `SwapSettings.tsx` still uses `#13141A`, `#1C1E24`, and `#22252F` — these should be converted to variables.)
- Nomenclature: `<area>-<element>` (`swap-modal-row`) and state suffixes `-checked`/`-unchecked`, `-selected`.
- Icons: `lucide-react`. Images: `next/image` with explicit `width`/`height`; assets in `public/brand`, `public/network`, `public/tokens`; fallback to `/tokens/generic.svg`.


## Contract conventions (Solidity)

- `pragma solidity 0.8.36;` or higher, SPDX MIT, `{ }` on a new line (do not use aggressive `forge fmt` settings that break this without running the full `forge fmt`).
- `require` with a message following the `"Contract: reason"` pattern (e.g., `"Router: expired"`); internal functions prefixed with `_`; immutable state marked as `immutable` whenever possible.
- The `Pair` is created via `create2` in the `Factory`—any change to the bytecode alters the pair addresses and requires regenerating the `PairInitCode` and redeploying the Factory and Router.
- Deploy scripts write directly to the chain's JSON using `JsonUtils.quote(...)` + `vm.writeJson(location, path, ".field")`; maintain this pattern in new scripts (and the write permission is already set in `foundry.toml`).
- New contracts go in `src/core` (protocol) or `src/periphery` (helpers/interfaces) and require tests in `test/` — CI runs `forge fmt --check`, `forge build --sizes`, and `forge test -vvv`.
